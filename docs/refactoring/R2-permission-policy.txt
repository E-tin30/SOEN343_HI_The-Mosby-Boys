PROPOSAL AND IMPLEMENTATION VERDICT

Catalogue refactoring: Extract Method, applied to one hotspot as team refactoring R2.

Implemented with modifications to the initial proposal:
1. Extract private requireCaller(User), requireOrder(Order) and
   requireRestaurant(Restaurant). Keep each call in its original validation order.
2. Extract private boolean canManageRestaurant(User, Restaurant). It returns true
   for an operator, or a restaurant-role caller whose id matches the target id.
   Public entry points validate null inputs before invoking this predicate.
3. Keep checkCanPause/Open/Close as public entry points, preserving their existing
   signatures and action-specific PermissionDeniedException messages.

Choices considered and not used:
- Objects.requireNonNull: it would throw NullPointerException instead of the
  existing PermissionDeniedException, changing observable behavior.
- One generic management-denial message: it would lose the pause/open/close
  messages that callers already receive.
- A new public canManageRestaurant API or separate policy hierarchy: four private
  helpers remove this repetition without changing callers or adding new types.
- Extra restaurant-status validation in the permission policy: these checks only
  authorize the caller; restaurant state-transition rules remain in the domain.

The agent checked the source, existing tests, new characterization tests, and the
final diff. The implementation verdict above records the agent's choices; Ashton
must read the tests and confirm the final report verdict in their own words.
